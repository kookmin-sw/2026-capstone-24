# 룸 상태 snapshot

**Parent:** [`_index.md`](../_index.md)

## Why

유저는 개인 방에서 악기를 배치하고, 오브젝트를 놓고, 리듬게임 악보를 설정하는 등 자신만의 합주 환경을 구성한다. 멀티 룸을 생성했을 때 이 환경이 그대로 옮겨가지 않으면 "내 방에 친구를 초대해 함께 합주" 라는 핵심 경험이 단절된다. 룸 생성 시 호스트의 개인 룸 상태를 룸 서버에 일관된 형식으로 전달해야 한다.

## What

개인 룸 상태를 멀티 룸의 초기 상태로 가져가는 데이터 흐름을 정의한다.

- **직렬화**: 개인 룸 상태(악기 배치·오브젝트 배치·오브젝트별 설정·악보 식별자 등)를 일관된 snapshot 표현으로 변환한다.
- **전송**: 클라이언트가 룸 생성을 요청할 때 snapshot을 함께 제출하고, 백엔드가 별도 관리 컴포넌트로, 별도 관리 컴포넌트가 claim된 룸 서버로 전달한다.
- **복원**: 룸 서버가 룸 진입 시점에 전달받은 snapshot으로 룸의 초기 상태를 구성한다.

## Behavior

- **Given** 호스트 유저가 개인 룸에서 자신의 합주 환경을 구성한 상태에서
  **When** 새 멀티 룸 생성을 요청하면
  **Then** 요청 페이로드에 직렬화된 snapshot이 포함되어 백엔드로 전달된다.

- **Given** 룸 서버가 룸으로 claim되어 RUNNING으로 전환되는 시점에
  **When** snapshot이 함께 전달되면
  **Then** 룸 진입 시점의 초기 상태가 snapshot 내용과 일치한다 (악기 배치·오브젝트 배치·악보 식별자 등).

- **Given** 멀티 룸에 입장하는 다른 유저가
  **When** 룸 세션에 합류하면
  **Then** 호스트와 동일한 초기 룸 상태를 관찰한다.

## Out of Scope

- snapshot의 DB 영속화 ([`02-user-persistence.md`](02-user-persistence.md) 확장 영역)
- 룸 종료 시 변경분을 다시 DB로 저장하는 양방향 동기화
- 멀티 룸 진행 중 추가된 악기/오브젝트의 영속 저장
- 리듬게임 결과·자유 합주 녹음 등 세션 결과물 저장
- 호스트가 떠난 뒤 다른 유저가 룸 상태를 *수정* 할 권한 정책
